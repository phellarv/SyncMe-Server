# SyncMe-Server TL;DR

Quickstart cheat sheet for running, verifying, and administering SyncMe-Server.

---

## 1. Quickstart (Docker Compose)

```bash
cd SyncMe-Server
cp .env.example .env

# Create client key directory with non-root ownership (default uid:gid 1000:1000; use sudo if needed)
sudo install -d -o 1000 -g 1000 -m 700 keys

# Generate the initial client API key (required before server start)
docker compose run --rm keys add laptop

# Start the server daemon
docker compose up -d --build
```
Default URL: `http://localhost:8000`

---

## 2. Quickstart (Local Python 3.12)

```bash
cd SyncMe-Server
python3.12 -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"
cp .env.example .env

# Generate client API key (creates <DATA_DIR>/keys.toml and prints token once)
python -m app.keys add laptop

# Run development server
uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
```

## 3. Essential Environment Configuration (`.env`)

Configure these settings in `.env` (or pass via shell environment variables):

```bash
SYNCME_KEYS_FILE="./keys/keys.toml" # Per-client keys (default: <DATA_DIR>/keys.toml)
DATA_DIR="./data"                   # Base directory for DB and server state
STORAGE_DIR="./storage"             # Base directory for workspace files, CAS objects, and archives
HOST="0.0.0.0"                      # Listen host
PORT=8000                           # Listen port
MAX_UPLOAD_BYTES=268435456          # Max upload payload (256 MiB)
```

### Storage Directory Layout

```
<STORAGE_DIR>/
├── workspaces/
│   └── {workspace_id}/               # Active synchronized files on disk
├── objects/
│   └── {workspace_id}/
│       └── {sha256[:2]}/{sha256[2:]} # Content-Addressable Storage (CAS) payloads
└── archive/
    └── {workspace_id}/               # Safety archives of deleted files
```

## 4. Verification with curl

Use the API key generated by `keys add`:

```bash
KEY="<key printed by keys add>"
WORKSPACE="default"
```

### Health Check (Unauthenticated)
```bash
curl -s http://localhost:8000/api/v1/health
# Response: {"status":"ok"}
```

### 1. Upload a New File (OCC guarded)
```bash
curl -s -X PUT "http://localhost:8000/api/v1/workspaces/${WORKSPACE}/files/notes/todo.txt" \
  -H "Authorization: Bearer ${KEY}" \
  -H 'If-Match: "0"' \
  --data-binary "Finish SyncMe documentation"
# Response: {"revision": 1}
```

### 2. Inspect Workspace Sync State
```bash
curl -s "http://localhost:8000/api/v1/workspaces/${WORKSPACE}/sync/state?since_revision=0" \
  -H "Authorization: Bearer ${KEY}"
```

### 3. Update File (Creates revision 2)
```bash
curl -s -X PUT "http://localhost:8000/api/v1/workspaces/${WORKSPACE}/files/notes/todo.txt" \
  -H "Authorization: Bearer ${KEY}" \
  -H 'If-Match: "1"' \
  --data-binary "Finish SyncMe documentation and add tests"
# Response: {"revision": 2}
```

### 4. Inspect File Version History (CAS)
```bash
curl -s "http://localhost:8000/api/v1/workspaces/${WORKSPACE}/history/notes/todo.txt?limit=10" \
  -H "Authorization: Bearer ${KEY}"
# Response:
# {
#   "path": "notes/todo.txt",
#   "history": [
#     {"revision": 2, "sha256": "...", "size": 39, "client_name": "laptop", "is_deleted": 0, ...},
#     {"revision": 1, "sha256": "...", "size": 27, "client_name": "laptop", "is_deleted": 0, ...}
#   ]
# }
```

### 5. Download Historical CAS Revision Content
```bash
curl -s "http://localhost:8000/api/v1/workspaces/${WORKSPACE}/revisions/1/notes/todo.txt" \
  -H "Authorization: Bearer ${KEY}"
# Returns exact bytes of revision 1 ("Finish SyncMe documentation")
```

### 6. Roll Back File to Revision 1 (Creates revision 3)
```bash
curl -s -X POST "http://localhost:8000/api/v1/workspaces/${WORKSPACE}/history/notes/todo.txt/restore" \
  -H "Authorization: Bearer ${KEY}" \
  -H "Content-Type: application/json" \
  -d '{"restore_revision": 1}'
# Response: {"path": "notes/todo.txt", "revision": 3, "new_revision": 3}
```

### 7. Delete File (Moves to safe archive & records tombstone)
```bash
curl -s -X DELETE "http://localhost:8000/api/v1/workspaces/${WORKSPACE}/files/notes/todo.txt" \
  -H "Authorization: Bearer ${KEY}" \
  -H 'If-Match: "3"'
# Response: {"revision": 4}
```

## 5. Client Key Administration

Manage per-client tokens using the key management CLI:

```bash
# Add a new client key (prints token once; copy immediately):
docker compose run --rm keys add phone

# List active clients (names and creation dates, never displays tokens):
docker compose run --rm keys list

# Revoke a client key:
docker compose run --rm keys revoke phone
```

*(Without Docker Compose, run: `python -m app.keys add <name>`, `python -m app.keys list`, or `python -m app.keys revoke <name>`)*

- **Last Key Protection:** The tool strictly prevents revoking the last remaining client key to avoid permanently locking clients out of the server.

## 6. Server Status & Client Monitoring

Inspect connected clients and workspace synchronization states:

```bash
# List clients and their connection status:
docker compose run --rm cli clients

# Global status and synchronization lag across workspaces:
docker compose run --rm cli status

# Detailed status and recent file activity for a client:
docker compose run --rm cli client status laptop
```

*(Without Docker Compose, run: `python -m app.cli clients`, `python -m app.cli status`, or `python -m app.cli client status <name>`)*
